
﻿# SOI configurable comparison

Audit: the original AdvancedComparator uses /analysis/compare, fixed territorial/retail dimensions and TOPSIS or weighted sum. Its source requirements can legitimately return 422; the original screen did not expose weights or criterion definitions. This flow is preserved in LegacyAdvancedComparator.jsx behind the existing-source analysis button. It is copied from the repository's parallel BACKSTAGE-3.1.0-main snapshot, which contains the original component. Existing APIs and database identifiers are unchanged.

The configurable SOI flow uses shared/soiComparison.mjs in both frontend and server. evaluateComparison({ candidates, criteria, observations }) returns status, errors, ranking, excluded, normalized weights, observed ranges and winner IDs. It requires 2-6 WGS84 candidates and 1-30 explicit criteria with name, definition, unit, source, weight, benefit/cost direction, minmax normalization, optional minimum/maximum restrictions and block/exclude/worst missing-data policy.

Measurements are explicitly supplied by the organization. Coordinates never produce inferred geographic scores. Unknown provenance defaults to UNKNOWN. Each contribution exposes raw value, source/date, normalized value and weight. Positive weights normalize to one. Constant columns receive 0.5. Missing values under worst policy contribute zero without fabricating a measurement; if bounds cannot be verified the candidate is excluded. At least two eligible candidates are required. Zero-weight criteria are ignored. Tied scores receive the same rank; ID determines only display order. Ranges are computed after exclusions. Changing candidates changes ranges and can change scores. GWO is deliberately unused: enumerating up to six supplied alternatives needs no stochastic optimizer.

The screen recalculates locally using useMemo and labels the calculation timestamp separately from measurement dates. It makes no claim of automatic external data refresh. Browser session drafts are scoped by organization and user and preserve criteria, observations, candidate edits, custom coordinate form and search query across map navigation. Existing map selection contracts (candidatePicker, candidates) remain. Saving POST /soi/comparisons sends the input snapshot; the server recomputes and persists it under the authenticated organization. Repeated save clicks are guarded and a stale save response does not label newer edits as saved. JSON export includes inputs, calculation version, contributions and exclusions. Draft storage is browser-session persistence, not a replacement for authorized server persistence.

Validation executed: node --test backend/domain/soiComparison.test.js (5 passed): reproducibility, benefit/cost orientation, 2/3/6 candidate counts, rejection of 0/1/7, WGS84 validation, malformed JSON, changing weights, invalid weights, missing data policies, restrictions, constant columns, explicit ties and zero-weight criteria. The root agent independently builds and validates the integrated frontend. No production data, credentials or external services are required by these tests.

Limitations: criterion sources and measurement timestamps are declarations and require organization review; a source string does not establish independent verification. There is no configured subscription to external comparison measurements. GPS, route optimization and terrain algorithms are independent of this deterministic ranking.
